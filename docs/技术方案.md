# 「5分钟」技术方案

> 版本：v0.1 · 前置文档：产品设计文档.md · 更新：2026-10-13

## 1. 技术选型总览

| 层 | 选型 | 备注 |
|---|---|---|
| 语言 | TypeScript（前后端统一） | 单仓库 monorepo |
| 后端 | Node.js + Fastify | MVP 不用 NestJS，保持轻量；结构按模块化组织，随时可迁 |
| 数据库 | SQLite（better-sqlite3） | 单机零运维，预留 PG 迁移路径 |
| 调度 | node-cron 轮询承诺表（1 分钟级） | 调度逻辑抽象成 `Scheduler` 接口，将来换 BullMQ+Redis 无痛替换 |
| AI | 大模型 API（工具调用） | 拆任务/降门槛改写/语气控制全部 prompt 驱动 |
| 前端 | Vue 3 + Vite + Tailwind CSS | 基于 Demo 三页结构重写为 H5 |
| 推送 | PWA Web Push（MVP）→ 企微机器人（二期） | 追问闭环的命脉是消息触达 |
| 部署 | 单进程 Docker 容器 | 静态前端 + API + Scheduler 同进程 |

## 3. 模块划分

| 模块 | 职责 | 关键点 |
|---|---|---|
| `server/api` | REST 接口，会话与任务 CRUD | 无鉴权起步（单用户本地部署），预留 token |
| `server/agent` | LLM 封装：系统提示词 + 工具调用（create_task / commit / complete） | 提示词是产品核心资产，单独文件版本化管理 |
| `server/scheduler` | 承诺到期扫描、追问触发、重试与温和收尾状态机 | 全项目最模块，需重点测试 |
| `server/push` | Web Push 发送与订阅管理 | 失败降级：站内消息 + 下次打开时补提醒 |
| `web/` | Vue 三页应用，复用 Demo 的交互流程与文案 | 状态管理 Pinia，极薄 |

## 4. 数据库表设计（核心 4 张）

```sql
-- 任务：含四象限与 5 分钟标记
tasks(id, title, quadrant, is_tiny, status, created_at, done_at)

-- 承诺：追问闭环的状态机载体
commitments(id, task_id, due_at, status, followup_count, next_action_at)
-- status: pending → asked → started | snoozed(→asked) | given_up
-- followup_count 上限 2（第三次敲门即危险阈值，见验证指标）

-- 对话记录
messages(id, role, content, created_at)

-- 胜利记录（完成即自动写入，供回顾页统计）
victories(id, task_id, note, created_at)
```

时间照妖镜的数据来源：`tasks.done_at - tasks.created_at` 对比 Agent 当初的预估（预估存在 commitments 或 tasks 的扩展字段）。

## 5. 追问闭环状态机（调度器核心）

```
用户承诺(20:00跑步，改写为5分钟版)
   → [pending] 到点扫描命中
   → 推送追问 → [asked]
      ├─ 回复"开始了" → [started] → 写入 victories
      ├─ 回复"再拖10分钟" → [snoozed] next_action_at+10min → 回到 [asked]（followup_count+1）
      └─ 回复"今天算了" → [given_up] → 次日 19:50 提前提醒（一次性）
```

## 7. 里程碑

| 阶段 | 交付 | 验证目标 |
|---|---|---|
| M1 | 调度器 + 承诺状态机 + SQLite + 单测 | 追问闭环在后端独立跑通（无 UI） |
| M2 | Agent 服务（LLM 拆解/改写/回复） + API | Demo 三页接真实后端 |
| M3 | Web Push + PWA | 手机上收到真实追问推送 |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| Web Push 触达率不稳定（iOS 限制多） | M3 同步验证企微机器人作为兜底渠道 |
| LLM 拆解质量不稳 | 工具调用强约束输出结构；失败时降级为固定模板话术 |
| 追问打扰导致关通知 | followup_count 硬上限 2；每日推送量统计入口 |
| 单测覆盖不足（AGENTS.md 要求） | M1 起状态机全部用例表格驱动测试，先测后交付 |
