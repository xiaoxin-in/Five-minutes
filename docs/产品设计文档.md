# 「5分钟」产品设计文档

> 版本：v0.1 · 状态：Demo 验证阶段 · 更新：2026-10-13

## 1. 一句话定位

一个帮你把「想做但一直没开始」的事，压缩到 5 分钟内启动的反拖延 Agent。

## 2. 为什么是 5 分钟

拖延症患者真正的问题不是不会管理时间，而是**启动门槛太高**。番茄钟的 25 分钟对他们是二次伤害——我们只需要 5 分钟：小到不好意思拒绝，大到足以完成"开始"这个动作。

## 3. 目标用户与核心痛点

| 痛点 | 场景 |
|---|---|
| 启动难 | 任务大而模糊（论文/报税/大扫除），本能回避 |
| 中断回不来 | 倒杯水顺手刷了 40 分钟手机 |
| 自我欺骗 | "等有状态再做"——状态永远不来 |
| 紧急度倒挂 | 重要不紧急的事（健康/学习）永远让路 |
| 烂尾自责循环 | 计划崩盘 → 自责 → 更拖延，意志力被情绪耗光 |
| 琐事堆积 | 每件 5 分钟但一直挂着，持续占用心理内存 |

## 4. 设计三原则

1. **队友，不是监工** —— 语气稍有说教感用户就会关通知，宁可少说话
2. **交互极轻** —— 一句话自然语言输入，Agent 负责结构化，绝不让用户填表单
3. **闭环要短** —— 每个功能一周内让用户感知到"有点用"，不靠长期坚持才见效

## 5. 功能设计

### MVP（Demo 已覆盖 ✅）

| 功能 | 对应痛点 | 说明 |
|---|---|---|
| 💬 对话主界面 | 启动难 | 自然语言入口；情绪优先响应（先接住"我又废了"，再给 5 分钟重启动作） |
| 🚀 2分钟启动器 | 启动难 | 把模糊任务拆到"小到不好意思拒绝"："写论文"→"打开文档写一句标题" |
| ⏰ 承诺追问闭环 | 自我欺骗 | 用户说"今晚8点跑步"，到点必追问，直到给出答复；可拖延一次（10 分钟后二次敲门），放弃则温和收尾、次日提前提醒 |
| 🧺 琐事批处理 | 琐事堆积 | 5 分钟清单攒批，Agent 在合适时机推送"正好有空，干掉这 3 件？" |
| 📋 待办 + 四象限 | 紧急度倒挂 | 自动归类，5 分钟任务打标（`5min`） |
| 🌱 微小胜利记录 | 烂尾自责 | 自动记录每天完成的事，周报对抗"我这周啥也没干"的认知偏差 |
| 🔍 时间照妖镜 | 自我欺骗 | 甩历史数据："上次你说 1 小时，实际 2.6 小时" |

### 后续版本（未实现）

- 焦点守护：工作会话中定时轻量检查，偏离时温和拉回
- 重要事项保底时间块：每天为"重要不紧急"强制预留 15 分钟

## 6. 核心操作流程（Demo 已跑通）

```
用户输入"我打算今晚8点跑步"
  → Agent 降门槛改写："20:00 穿运动鞋下楼站 5 分钟"（自动入待办）
  → 时间到 → 主动追问："开始了吗？"
      ├─ 开始了 → 启动成功，记入胜利清单
      ├─ 再拖10分钟 → 温和接受，10分钟后二次敲门
      └─ 今天算了 → 不说教，"取消一次 ≠ 失败"，次日 19:50 提前提醒
```

## 7. 技术形态（规划）

- **MVP**：定时任务 + IM 式对话（先跑通追问闭环，不做 App）
- **Demo 现状**：纯前端单文件（`demo/index.html`），模拟数据 + 关键词规则匹配
- 数据模型核心实体：任务（含象限/5分钟标记）、承诺（时间点+追问状态）、胜利记录、历史耗时统计

## 8. 验证指标（Demo 之后要回答的问题）

1. 追问的打扰度：追问几次用户会关通知？（预期：≥3 次/天即危险）
2. 启动改写接受率：用户愿意点"开始了"的比例
3. 周留存：胜利清单是否足以形成"每周日想看一眼"的习惯
